# Installation with Helm

[Helm](https://helm.sh/docs) is the package manager for Kubernetes. A Helm [chart](https://helm.sh/docs/topics/charts/) is a package that contains all the necessary files to deploy kubernetes resources /application to a Kubernetes cluster.

Helm charts for the component can be found here:

- [Percona Operator for Postgres](https://github.com/percona/percona-helm-charts/tree/main/charts/pg-operator)
- [Percona Postgres Cluster](https://github.com/percona/percona-helm-charts/tree/main/charts/pg-db)

## Prerequisites

Before installing the Percona PostgreSQL Operator with Helm, ensure you have:

1. **Helm v3** installed and configured
   - [Install Helm](https://helm.sh/docs/intro/install/)
   - Verify installation: `helm version`

2. **kubectl or oc(optional)** command-line tool installed and configured to access your Kubernetes/OpenShift cluster
   - For kubectl: [Install kubectl](https://kubernetes.io/docs/tasks/tools/install-kubectl/)
   - For oc: [Install oc](https://docs.okd.io/latest/cli_reference/openshift_cli/getting-started-cli.html)

3. **A Kubernetes or OpenShift environment** that meets the [system requirements](../docs/System-Requirements.md)

4. **Privileges** to create Custom Resource Definitions (CRDs), RBAC resources, and deploy the Operator

## Installation Procedure

The installation consists of following steps:
1. Installing the Percona Operator for PostgreSQL Helm Chart
2. Installing the Percona PostgreSQL cluster Helm Chart(requires the operator to be running)

### Installation of Percona Operator for PostgreSQL

#### Step 1: Add Percona Helm Repository

Add the Percona Helm charts repository and update your Helm client:

```bash
helm repo add percona https://percona.github.io/percona-helm-charts/
helm repo update
```

Verify the repository was added successfully:

```bash
helm repo list
```

You should see the `percona` repository in the list.

#### Step 2: Create a Namespace

It is a good practice to isolate workloads in Kubernetes by installing the Operator in a dedicated namespace. Create a namespace for the Operator:

```bash
kubectl create namespace postgres-operator
```

!!! note "Namespace Selection"
    You can use any namespace name you prefer. If you choose a different name, make sure to replace `postgres-operator` in all subsequent commands. You can also deploy to the `default` namespace by omitting the `-n` parameter.

#### Step 3: Install the Operator

The Operator can be installed in **Namespaced Mode** or **Cluster-Wide Mode**. For details on the available deployment modes, see [Namespaced Modes](./2.1.6.1_namespace_modes.md).

Additional Operator configuration options are described in [Operator Configurations](./2.1.6_operator_configurations.md).
To customize the Helm chart, review the available configurable [parameters](https://github.com/percona/percona-helm-charts/tree/main/charts/pg-operator#configuration) and set the appropriate values using any of the supported methods outlined in the [Helm documentation](https://helm.sh/docs/chart_template_guide/values_files/)

##### Option 1: Namespaced Mode (Default)


This installation:
- Creates Custom Resource Definitions (CRDs)
- Sets up Role-Based Access Control (RBAC) with necessary permissions using `Role`,`RoleBinding` and `ServiceAccount`
- Deploys the Operator to watch for PostgreSQL clusters in only the namespace where it's installed

Install the Operator in **Namespaced Mode** using the `pg-operator` Helm chart.

```bash
helm install pg-operator percona/pg-operator \
  --namespace postgres-operator \
  --create-namespace
```

If there are any configurations done for the parameters, use the `--set` flag or a values file 
For example: changing the log structure from plain text to JSON, we should set the value `logStructured` to `true` for the charts.

**Using --set flag**: 
```bash
helm install pg-operator percona/pg-operator \
  --namespace postgres-operator \
  --set logStructured=true \
  --create-namespace 
```
**Using values file**: 
Create a file named `namespaced-values.yaml`:
```bash
logStructured: true
```

Install the chart
```bash
helm install pg-operator percona/pg-operator \
  --namespace postgres-operator \
  --create-namespace \
  -f namespaced-values.yaml
```

The `pg-operator` parameter is the name of a new [Helm release object](https://helm.sh/docs/intro/using_helm/#three-big-concepts) which is created for the Operator when you install its Helm chart (use any name you like).



##### Option 2: Cluster Wide Mode

This installation:
- Creates Custom Resource Definitions (CRDs)
- Sets up Role-Based Access Control (RBAC) with necessary permissions using `ClusterRole`,`ClusterRoleBinding` and `ServiceAccount`
- Deploys the Operator to watch for PostgreSQL clusters in all the namespaces of the kubernetes cluster or the namespaces set in `watchNamespace` variable

To install the Operator in **Cluster Wide Mode**, you need to install the Helm chart with any one of the below options for the chart values:
1. Set `watchAllNamespaces=true` to manage all namespaces
2. Set `watchNamespace` to a list of namespaces to manage Postgres Cluster.Example `watchNamespace="namespace1,namespace2"`

**Using --set flag:**

```bash
helm install pg-operator percona/pg-operator \
  --namespace postgres-operator \
  --create-namespace \
  --set watchAllNamespaces=true 
```

**Using a values file:**

Create a file named `operator-values.yaml`:
```yaml
watchAllNamespaces: true
# watchNamespace: ""  # Empty string means watch all namespaces
```

Install with the values file:

```bash
helm install pg-operator percona/pg-operator \
  --namespace postgres-operator \
  --create-namespace \
  -f operator-values.yaml
```

!!! note "Watch Specific Namespaces"
    To monitor only a set of namespaces rather than all namespaces, set `watchNamespace` to a comma-separated list. For example to manage clusters only in namespace1,namespace2 do the following
    
    ```yaml
    watchNamespace: "namespace1,namespace2"
    ```
    or use the flag `--set watchNamespace="namespace1,namespace2"`
    
    This will manage PostgreSQL clusters in `namespace1` and `namespace2`.

[Refer](./2.1.6.1_namespace_modes.md#cluster-wide-deployment) for more information on cluster-wide deployment.

#### Step 4: Verify Operator Installation

Check that the Operator Pod is running:

```bash
kubectl get pods -n postgres-operator
```

You should see the Operator Pod in `Running` status. The Operator is now ready to manage PostgreSQL clusters.

Check the logs of the operator to see if there are any issues:

```bash
kubectl logs deploy/percona-postgresql-operator -n postgres-operator
```

If there are more than one replica of the operator, check the logs of individual operator pod. Operator works on a leader follower model and only one pod will have the relevant logs for reconciliation.

Verify the Helm release:

```bash
helm list -n postgres-operator
```

### Installation of PostgreSQL Cluster

#### Step 1: Create a PostgreSQL Cluster

After the Operator is installed and running, you can Install a PostgreSQL cluster using the [pg-db Helm chart](https://github.com/percona/percona-helm-charts/tree/main/charts/pg-db).

To customize the Helm chart, review the available configurable [parameters](https://github.com/percona/percona-helm-charts/tree/main/charts/pg-db#installing-the-chart) and set the appropriate values using any of the supported methods outlined in the [Helm documentation](https://helm.sh/docs/chart_template_guide/values_files/)
The Operator will automatically manage the cluster lifecycle.
**For production deployments, it is strongly recommended to configure parameters for Patroni, PostgreSQL, Proxy, and other components based on the specific characteristics of your workload, rather than relying on default configurations.**
[Refer](./2.6_postgres_configurations.md) for more information.

Install a PostgreSQL cluster with default configurations:
```bash
helm install cluster1 percona/pg-db \
  --namespace postgres-operator
```

If any customizations are required, set the appropriate values as needed. For example:
- PostgreSQL version 16 (postgresVersion=16)
- Configure three PostgreSQL replicas (instances.replicas=3)

The commands below show both ways to perform this operation.

**Using `--set` flags:**

```bash
helm install cluster1 percona/pg-db \
  --namespace postgres-operator \
  --set postgresVersion=16 \
  --set instances.replicas=3 \
```
**Using a values file:**

Create a file named `cluster-values.yaml`:
```yaml
postgresVersion: 16
instances: 3
```

Install with the values file:
```bash
helm install cluster1 percona/pg-db \
  --namespace postgres-operator \
  -f cluster-values.yaml
```

The `cluster1` parameter is the name of a new [Helm release object](https://helm.sh/docs/intro/using_helm/#three-big-concepts) which is created for the PostgreSQL cluster when you install its Helm chart (use any name you like).

Cluster creation may take from a minute up to several minutes, depending on network conditions and available resources.
