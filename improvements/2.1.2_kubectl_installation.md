# Installation with kubectl/oc

This method involves applying YAML manifests to your Kubernetes cluster using the Kubernetes command-line tool `kubectl` or OpenShift's `oc` command. Both commands work identically for this installation process. All examples in this document use kubectl. For OpenShift, you can substitute kubectl with oc and run the commands unchanged.

## Prerequisites

Before installing the Percona PostgreSQL Operator, ensure you have:

1. **kubectl or oc** command-line tool installed and configured to access your Kubernetes/OpenShift cluster
   - For kubectl: [Install kubectl](https://kubernetes.io/docs/tasks/tools/install-kubectl/)
   - For oc: [Install oc](https://docs.okd.io/latest/cli_reference/openshift_cli/getting-started-cli.html)
   
2. **A Kubernetes or OpenShift environment** that meets the [system requirements](../docs/System-Requirements.md)

3. **Privileges** to create Custom Resource Definitions (CRDs), RBAC resources, and deploy the Operator. Run the [script](./check_priviliges.sh) to verify if all the needed priviliges are present.


## Installation Procedure

The installation consists of following steps:
1. Installing the Percona Operator for PostgreSQL
2. Creating a Percona PostgreSQL cluster (requires the operator to be running)

### Installation of Percona Operator for PostgreSQL

Clone the percona-postgresql-operator repository to do any modifications in the manifests before installation.

    ```bash
    git clone -b v{{ release }} https://github.com/percona/percona-postgresql-operator
    cd percona-postgresql-operator
    ```

Alternatively, you can apply the manifests directly from the Git repository. However, any modifications require copying the files locally.

#### Step 1: Create a Namespace

It is a good practice to isolate workloads in Kubernetes by installing the Operator in a dedicated namespace. Create a namespace for the Operator:

```bash
kubectl create namespace pg-operator
```

!!! note "Namespace Selection"
    You can use any namespace name you prefer. If you choose a different name, make sure to replace `pg-operator` in all subsequent commands. You can also deploy to the `default` namespace by omitting the `-n` parameter.

### Step 2: Install the Operator

Operator can be installed in Namespaced Mode or Cluster Wide Mode. [Refer](./2.1.6.1_namespace_modes.md) for more information.
For other Operator configurations,[Refer](./2.1.6_operator_configurations.md)

#### Option-1: Namespaced Mode (Default)

Edit the file `bundle.yaml` for any configuration changes needed and Deploy the Operator in **Namespaced Mode**.
The bundle file is a cumulation of the following files:( TO-DO: Anastasia: Link correct files from the repo)
- crd.yaml: Creates Custom Resource Definitions (CRDs)
- rbac.yaml: Sets up Role-Based Access Control (RBAC) with necessary permissions. Creates Role,RoleBinding,ServiceAccount
- operator.yaml: Deploys the Operator to watch for Postgres Cluster in only one namespace where it's installed.


```bash
kubectl apply --server-side -f deploy/bundle.yaml -n pg-operator
```

#### Option-2: Cluster Wide Mode

Edit the file `cw-bundle.yaml` for any configuration changes needed and Deploy the Operator in **Cluster Wide Mode**.
The bundle file is a cumulation of the following files:( TO-DO: Anastasia: Link correct files from the repo)
- crd.yaml: Creates Custom Resource Definitions (CRDs)
- cw-rbac.yaml: Sets up Role-Based Access Control (RBAC) with necessary permissions. Creates ClusterRole,ClusterRoleBinding,ServiceAccount
- cw-operator.yaml: Deploys the Operator

```bash
kubectl apply --server-side -f deploy/cw-bundle.yaml -n pg-operator
```

Above command installs the operator in cluster wide mode and manages Postgres Clusters in all namespaces.
[Refer](./2.1.6.1_namespace_modes.md#cluster-wide-deployment) for more information

!!! note "Install in other Namespaces"
To install operator in cluster wide mode in other namespace, change the namespace of the Service Account in cw-bundle.yaml
```
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: percona-postgresql-operator
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: percona-postgresql-operator
subjects:
- kind: ServiceAccount
  name: percona-postgresql-operator
  namespace: pg-operator   # <--- Change this field to the namespace where operator is being installed.
```
!!! note "Manage specific Namespaces"
To monitor only set of namespaces rather than all the namespaces, change the value of the environment variable WATCH_NAMESPACE of the Deployment to comma seperated list.
```
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: percona-postgresql-operator
  ...
spec:
  ...
  template:
    ...
    spec:
      containers:
      - env:
        - name: WATCH_NAMESPACE  
          value: "namespace1,namespace2"  # <--- Change the value of WATCH_NAMESPACE to watch for specific namespaces. This will manage Postgres Clusters in namespace1,namespace2
```
### Alternative: Component wise Installation of Operator

Instead of using the bundle file, you can install components individually for more control. This can be handy when configurations of the specific components needs to be changed.

1. **Install Custom Resource Definitions:**
   ```bash
   kubectl apply --server-side -f deploy/crd.yaml
   ```

2. **Install RBAC:**

    Option-1: For Namespaced Mode
   ```bash
   kubectl apply -f deploy/rbac.yaml -n pg-operator
   ```
    Option-2: For Cluster Wide Mode
   ```bash
   kubectl apply -f deploy/cw-rbac.yaml -n pg-operator
   ```

3. **Deploy the Operator:**
    Option-1: For Namespaced Mode
   ```bash
   kubectl apply -f deploy/operator.yaml -n pg-operator
   ```
    Option-2: For Cluster Wide Mode
   ```bash
   kubectl apply -f deploy/cw-operator.yaml -n pg-operator
   ```


### Step 3: Verify Operator Installation

Check that the Operator Pod is running:

```bash
kubectl get pods -n pg-operator
```
You should see the Operator Pod in `Running` status. The Operator is now ready to manage PostgreSQL clusters.
Check the logs of the operator to see if there are any issues

```bash
kubectl logs deploy/percona-postgresql-operator -n pg-operator
```
If there are more than one replica of the operator, check the logs of individual operator pod. Operator works on a leader follower model and only one pod will have the relevant logs for reconciliation.


### Installation of PostgreSQL Cluster

### Step 1: Create a PostgreSQL Cluster

After the Operator is installed and running, you can create a PostgreSQL cluster. The Operator will automatically manage the cluster lifecycle.
Edit the file `cr.yaml` for any configuration changes, [Refer](./2.6_postgres_configurations.md) for more information.
**For production deployments, it is strongly recommended to configure parameters for Patroni, PostgreSQL, Proxy, and other components based on the specific characteristics of your workload, rather than relying on default configurations.**

```bash
kubectl apply -f deploy/cr.yaml -n pg-operator
```
This creates a PostgreSQL cluster with default configurations if no changes are made to the cr.yaml file. Otherwise, the PostgreSQL cluster will be created using the configurations specified by the user. Cluster creation may take from a minute up to several minutes, depending on network conditions and available resources.
