# Percona PostgreSQL Operator

## What is Percona PostgreSQL Operator?

The Percona PostgreSQL Operator is a Kubernetes Operator that automates the deployment, management, and day-to-day operations of PostgreSQL database clusters on Kubernetes. It extends the Kubernetes API with Custom Resources, allowing you to manage PostgreSQL clusters declaratively using Kubernetes-native tools.

You simply define your desired PostgreSQL cluster state in a Custom Resource YAML file. The Operator then automatically creates, configures, and maintains all the necessary Kubernetes objects to bring your PostgreSQL cluster to life and keep it running.

The Operator is built on Percona PostgreSQL best practices and includes enterprise-grade tools like Patroni for high availability, pgBackRest for backups, and pgBouncer for connection pooling. 

Percona PostgreSQL operator is a fork of crunchy operator, Percona is actively involved in contributing back to the community.

**All components of the stack are fully open source, including the Kubernetes operator, PostgreSQL database, backup and high-availability tooling, and the complete monitoring and observability stack.**

## Salient Features of Percona PostgreSQL Operator

### 1. High Availability and Automatic Failover

- **Patroni Integration**: Integration of Patroni, a high-availability framework specifically designed for PostgreSQL, for automatic leader election and failover.
- **Zero Data Loss Failover**: WAL-based streaming replication ensures no data loss during automatic failover.
- **Health Monitoring**: Continuous monitoring of PostgreSQL health and triggers failover automatically.
- **Manual Switchover**: Supports safe, controlled manual promotion of replicas to primary for maintenance operations

### 2. Enterprise grade Backup and Restore with pgBackRest

- **Multiple Backup Type Support**: Supports full, incremental, and differential backups
- **Point-in-Time Recovery (PITR)**: Improved Recovery Point Objective(RPO) with ability to restore to a specific point in time using WAL archives
- **Automated Backup Scheduling**: Configure cron-based schedules for automated backups
- **Multiple Storage Backends**: Support for S3-compatible storage and local PersistentVolumes
- **Backup Encryption**: Secure backups with encryption at rest
- **Backup Retention Policies**: Automatically manage backup retention and cleanup

### 3. Connection Pooling with pgBouncer

- **Connection Efficiency**: Reduces PostgreSQL connection overhead by pooling client connections
- **Transaction-Level Pooling**: Efficiently manage connections at the transaction level
- **Reads Load Balancing**: Automatically distribute read queries across replica instances
- **High Availability**: pgBouncer replica instances provides redundancy
- **Seamless Integration**: Automatically configured and managed by the Operator

### 4. Automated Cluster Management

- **Declarative Configuration**: Cluster specifications are defined in YAML. Operator handles the automation 
- **Automatic Scaling**: Scale clusters up or down by adjusting replica counts in the Custom Resource
- **Dynamic Configuration**: Update PostgreSQL parameters without restarting the cluster
- **Self-Healing**: Automatically detects and recovers from pod crashes, node failures, and network issues
- **Rolling Updates**: Safely update cluster configurations with zero-downtime rolling updates
- **Storage Autoscaling**: Automatically increase storage of Postgress Nodes

### 5. PostgreSQL-Specific Features

- **WAL Management**: Optional dedicated storage for Write-Ahead Logs (WAL) for improved performance
- **Tablespaces**: Support for custom tablespaces with dedicated storage volumes
- **PostgreSQL Extensions**: Built-in support for pg_stat_monitor, pgAudit, set_user, wal2json, and custom extensions
- **User and Database Management**: Automatically create users, databases, and manage credentials
- **Init SQL Scripts**: Execute custom SQL scripts during cluster initialization

### 6. Standby Clusters for Disaster Recovery

- **Disaster Recovery**: Provides robust disaster recovery capabilities with backups or streaming replication
- **Multi Cloud/Multi Kubernetes**: Primary cluster and DR site cluster can run in different namespaces or different kubernetes clusters
- **Failover Capability**: Standby clusters can be promoted to primary in disaster scenarios


### 7. Security Features

- **Encryption at Rest**: Encryption at rest with pg_tde
- **TLS Encryption**: Encrypt connections between clients and PostgreSQL, and between cluster members
- **Certificate Management**: Support for custom TLS certificates and certificate generation with cert manager

### 8. Monitoring and Observability

- **PMM Integration**: Native integration with Percona Monitoring and Management (PMM)
- **pg_stat_monitor**: Advanced query performance monitoring with query fingerprinting
- **Comprehensive Metrics**: Track connection counts, transaction rates, cache hit ratios, replication lag, and more
- **Query Analytics**: Helps in troubleshooting database queries and optimize database performance (https://docs.percona.com/percona-monitoring-and-management/2/get-started/query-analytics.html)

### 9. Operator Capabilities

- **Selective Namespace Reconciliation**: It is possible to define the namespaces where PG clusters need to be reconciled. This can be a single namespace, a set of namespaces, or all namespaces in a cluster-wide mode.
- **Concurrency**: Supports concurrent reconciliations, which is beneficial for managing PostgreSQL clusters at large scale.



## Summary

The Percona PostgreSQL Operator transforms PostgreSQL from a complex application requiring manual configuration and ongoing operational expertise into a Kubernetes-native resource that can be managed like any other Kubernetes workload. It automates the entire lifecycle of PostgreSQL clusters, from initial deployment through day-to-day operations, backups, scaling, and disaster recovery.

By combining PostgreSQL expertise with Kubernetes automation, the Operator eliminates much of the complexity and risk associated with manual database management, allowing teams to focus on building applications rather than managing database infrastructure.
If needed, enterprise-grade support is available with Percona, providing expert assistance, SLAs, and production support for PostgreSQL and Kubernetes environments.
